# 読書ノート運用マニュアル（あなたがやること）

読書ノート（本の引用データベース）を1冊公開するまでの流れのうち、あなたが実際に手を動かす箇所だけをまとめたもの。パイプライン全体の技術的な詳細は `rekishi-hp/CLAUDE.md` の「読書ノートを追加するとき」チェックリストを参照。

## 全体の流れ（9ステップ、太字があなたの操作）

```
①本を読んで印をつける → ②画像化してDriveに置く → ③GASを実行 →
④Vaultをダウンロード → ⑤generate.pyを実行 → ⑥Claudeにレビューを依頼 →
⑦コミットを承認 → ⑧（任意）書影を置く → ⑨（任意）Obsidianに反映
```

---

## ① 本を読みながら印をつける（あなたの作業）

3種類の印だけ覚えておけばOK（`gas_vault.js`に定義済み）。

| 印 | 意味 |
|---|---|
| ◎ | 最重要。その行・段落まるごと引用対象 |
| 縦線（余白に縦の線） | 隣接するテキストブロックを引用対象 |
| 横線（文字の下に線） | その行・段落を引用対象 |

ここでの判断が最終的な引用の「原材料」になる。後工程のAIは印のない場所を勝手に拾わない。

## ② ページを撮影・スキャンし、Google Driveに配置する（あなたの作業、自動化不可）

Drive の `books-vault/[slug]/` フォルダに以下を置く。

- `page_001.jpg` など、印をつけたページの画像
- `meta.json`（書誌情報。無くてもファイル名から自動生成は試みるが、精度が落ちるので作るのを推奨）

```json
{
  "title": "明日のための近代史",
  "author": "伊勢弘志",
  "year": 2022
}
```

（`merged_doc_name`と`concepts_hint`は任意項目なので省略可）

## ③ GAS（Google Apps Script）で `processBook()` を実行する（あなたの操作、中身はAI）

GASエディタで `TARGET_SLUG` に対象のslugを設定し（またはコード内の`SLUG`定数を書き換え）、`processBook()` を選んで実行ボタンを押すだけ。

- 中でAI（Gemini Vision）が画像の印を読み取り、Drive上に `books-vault/[slug]/[slug].md`（Vault＝全引用）を生成する
- **同時に、レビュー前の版が自動でGitHubにcommitされる**（`GITHUB_TOKEN`設定済みのため）。仕様として把握しておくだけでよく、何もしなくてよい（後で⑦が上書きする）
- 画像が多く1回で処理しきれない場合（15枚ずつ処理）、「未処理ページが残っています」と出たら再度実行する

## ④ VaultをDriveからローカルにダウンロードする（あなたの作業、自動化不可）

Driveの `books-vault/[slug]/[slug].md` をブラウザでダウンロードし、ローカルの `rekishi-hp/books-vault/[slug].md` に置く。

**ここだけは意図的に自動化していない。** 過去にClaudeがDrive APIごしにこのファイルを取得しようとして文字化けを起こした事故があり、引用の正確性がこのサイトの価値そのものなので、リスクを取らない運用にしている。

## ⑤ `generate.py` を実行する（あなたの操作、中身はAI選定）

```bash
cd rekishi-hp/books-vault
python generate.py [slug]
```

Vault全引用の中から、授業との接続性を軸にAIが20〜25件を選び、`src/content/books/[slug].md` を生成する。実行後にターミナルへ警告（短すぎる引用・記号混入など）が出ることがあるが、この時点では何もしなくてよい。次の⑥でまとめて対処する。

## ⑥ Claude Codeに `/読書ノート公開レビュー [slug]` を依頼する（あなたは指示するだけ）

チャットで一言頼むだけ。

```
/読書ノート公開レビュー [slug]
```

これで以下がすべて自動で行われる：
- ⑤で出た警告への対応（除外／記号除去の判断）
- 他の授業単元・他の本を実際に読んでの `relatedUnits` / `relatedBookLinks` の関連付け判断
- 書影の有無確認
- `astro build` によるビルド確認

## ⑦ コミットしてよいか聞かれたら承認する（あなたの判断）

⑥の最後に内容のサマリーが出るので、目を通して「進めて」と答えるだけ。ここは**Claudeが自分の判断だけでは絶対にpushまで進めない**。

## ⑧ （その本の書影がまだ無ければ）表紙画像を置く（あなたの作業）

`rekishi-hp/src/assets/covers/[slug].jpg`（または`.png`/`.webp`）に置くだけで、frontmatterの編集は不要。⑥のレビューで「未設置」と言われたときだけ対応すればよい。

## ⑨ （必要なタイミングで）Obsidianに反映する（あなたが実行を指示）

現状、自動実行の仕組み（`sync_citations.ps1`）はまだWindowsのタスクスケジューラに未登録なので、**今のところは毎回あなたが実行を思い出す必要がある**。Claudeに「Obsidianに同期して」と頼めば`import_citations.py`を実行する。ただし壊れた本（トークン切れ等）が残っている間は実行を控えるようClaude側で止める。

## この他、頻度は低いが覚えておくべきこと

| いつ | あなたがやること |
|---|---|
| 引用選定の基準（`generate.py`のプロンプト）を変えたとき | `gas_vault.js`側も同じ内容に手動で書き換え、**GAS Apps Scriptエディタに貼り直す**（コードをpushしただけでは反映されない） |
| 公開済みの引用を気に入らなくて差し替えたいとき | Claudeに`/引用差し替え`を依頼するだけ |
| 概念タグのマスター語彙を追加したとき | `gas_vault.js`内の埋め込み語彙も手動で同期し、貼り直す |
