# 歴史シミュレーション — CLAUDE.md

高校生向けの歴史人物視点シミュレーションゲーム（ビジュアルノベル形式）。  
HTML単体ファイルで動作し、授業でブラウザから即時利用できる形式を維持する。

---

## プロジェクト構造

```
歴史シミュレーション/
├── index.html                         ← シナリオ選択画面（トップページ）
├── CLAUDE.md                          ← この指示書
└── scenarios/
※ 読書データは ../books/ に移動済み（授業自動生成と共有）
    ├── 01_日露戦争_桂太郎/
    │   ├── index.html                 ← ゲーム本体（単体HTML）
    │   ├── game_original.html         ← バックアップ
    │   └── images/                    ← ローカル保存の人物写真（任意）
    ├── 02_（次のシナリオ名）/         ← 第2回授業分
    │   └── index.html
    └── _template/                     ← 新シナリオ作成用のひな型
```

## シナリオ作成の手順

### Step 1：人物・テーマと対象概念の選定
- 教科書の画像をClaudeCodeにアップロードする
- ClaudeCodeが画像を読み取り、登場人物・時代・単元を把握し、シナリオ候補を複数提案する
- 各候補に対して「このシナリオが深めさせる中核的な概念」を1〜2個提示する
- **必ず先生に確認を取ってから Step 2 以降に進む**（概念とシナリオの両方を確認）
- プレイヤーの立場は特定の人物に限らず、民衆・労働者・国民・植民地の人々などの抽象的な立場でもよい

### Step 2：資料収集（優先順位あり）
**必ず以下の優先順位で参照する：**

1. **最優先：ローカルの読書データ**（信頼性が高い学術書・専門書）
   - フォルダ: `books/`（プロジェクトルート直下・授業自動生成とも共有）
   - `Read` ツールで直接ファイルを読み込む（MCP不要・オフライン動作）
   - 特に歴史シナリオに関係が深い書籍を選んで参照すること（下記リスト参照）

2. **概念確定の参照：中核概念参考資料**（次期学習指導要領の方向性）
   - フォルダ: `../参考資料/`（`Read` ツールで参照可能）
   - 対象概念を選定・説明する際に必ず参照すること
   - `中核概念（ChatGPT①）.pdf`：第2次概念6個＋実質概念9個の仮案（本CLAUDE.mdの概念一覧の出典）
   - `中核概念（Claude）.pdf`：超上位概念・歴史総合固有概念・探究操作概念の三層構造モデル
   - `高校歴史総合の中核的概念モデル.docx`：三層モデルの詳細版

3. **補助：ウェブ検索・Wikipedia等**
   - `books/` フォルダに該当資料がない時代・人物の場合のみ使用
   - 使用した場合は「参考：〇〇（Web情報）」と明記する

### Step 3：シナリオ執筆
- `scenarios/_template/` のひな型をコピーして新フォルダを作成
- `index.html` を編集してシナリオを記述

### Step 4：キャラクター画像の生成（任意）
- `generate_images.py` で DALL-E 3 によるイラストを生成し `images/` に保存する
- 詳細は「キャラクター画像生成ツール」セクションを参照

### Step 5：`index.html`（トップ画面）を更新
- `歴史シミュレーション/index.html` の `scenarios-grid` に新しいカードを追加する

## シナリオ設計の原則

### 教育目標
- 生徒が「当時の人物・立場の制約」を体感する
- 「なぜそう判断したか」の合理性を理解させる（正解当てゲームにしない）
- **各シナリオは必ず1〜2個の「中核的な概念」の理解を深めることを主目的とする**
- エンディングの概念カード4枚は、対象概念に直接つながる内容にする

### 中核的な概念一覧（次期学習指導要領 2030年度実施予定）

> **出典：`../参考資料/` フォルダの資料に基づく。**  
> 概念の選定・説明文の作成時は `Read` ツールで当該PDFを直接参照すること。  
> 詳細な定義・核心の問い・現代社会への接続例は参考資料に記載されている。

シナリオ作成前に、以下から対象概念を1〜2個選び、先生の確認を得ること。

**A. 第2次概念（思考の枠組み）**（出典：`中核概念（ChatGPT①）.pdf`）

| # | 概念名 | 核心の問い |
|---|---|---|
| ① | 変化と継続 | 何が変わり、何が変わらなかったのか？ |
| ② | 因果と帰結 | なぜそうなったのか？意図せざる結果は何か？ |
| ③ | 歴史的重要性 | 誰が、なぜ「重要」と判断したのか？ |
| ④ | 歴史的パースペクティブ | 当時の人々はどんな世界認識のもとで判断したのか？ |
| ⑤ | 解釈と論争性 | 同じ出来事を異なる立場はどう解釈するか？ |
| ⑥ | 比較と相互の関連 | 異なる地域・時代の出来事は何が共通し、何が違うか？ |

**B. 実質概念（内容知的概念）**（出典：`中核概念（ChatGPT①）.pdf`）

| # | 概念名 | 核心の問い |
|---|---|---|
| ⑦ | 近代化 | 近代化は人々に自由を広げたか、新しい支配を生んだか？ |
| ⑧ | 国民国家とナショナリズム | 国民国家は誰を「国民」とし、誰を排除したか？ |
| ⑨ | 帝国主義と植民地主義 | 帝国であった経験は今の東アジア関係にどんな遺産を残したか？ |
| ⑩ | 市民権・人権の拡張 | 「人権」は普遍的なものか、それとも特定の時代の所産か？ |
| ⑪ | 大衆化と総力戦 | 大衆参加の拡大は民主化と戦争動員をなぜ同時に進めたのか？ |
| ⑫ | グローバル化と相互依存 | グローバル化は誰を豊かにし、誰を取り残してきたか？ |
| ⑬ | 自由と統治（権力と権利） | 「自由」を制限することは、いつ・誰によって正当化されてきたか？ |
| ⑭ | 平等と格差 | 「機会の平等」と「結果の平等」のどちらが歴史的により拡大したか？ |
| ⑮ | 開発と環境 | 経済発展は長期的に人間社会の存立基盤にどんな影響を与えるか？ |

**C. 三層構造フレームワーク（出典：`中核概念（Claude）.pdf`）**

上記A・Bの概念を、以下の三層に配置して読むとシナリオの「説明の軸」が定まりやすい。

| 層 | 役割 | 概念（例） |
|---|---|---|
| **構造層**（超上位概念） | どの時代・地域にも現れる、事件の背後構造を説明する軸 | 権力・国家・市場・共同体・正統性と権利・技術と情報・移動と交流・暴力 |
| **変化層**（歴史総合固有概念） | 近現代の大転換を名指す概念。単元の焦点化に使う | 近代化・産業化・国民国家・帝国主義・大衆化・総力戦・冷戦・脱植民地化・グローバル化 |
| **探究層**（操作概念） | 歴史をどう説明し・論証するかを支える枠組み | 因果と帰結・変化と継続・比較・観点と立場・史料と証拠・歴史的意義 |

シナリオ設計の実践例（桂太郎シナリオ）：
- 構造層：**国家 × 市場 × 暴力**（日露戦争の背後構造）
- 変化層：**帝国主義**（近代国家の対外膨張）
- 探究層：**② 因果と帰結・④ 歴史的パースペクティブ**（選択した概念）

### 構成パターン（桂太郎シナリオに準拠）
1. **導入ストーリー**：人物・時代背景・対立軸を提示
2. **状況説明**（2〜3シーン）：当時の制約・情報を整理
3. **決断場面**（3〜4回）：A/B/Cの選択肢 → 結果表示 → 史実解説
4. **エンディング**：史実の結末 + 選択記録スコア + **歴史的概念カード（4枚）**

### 決断場面の設計ルール
- 選択肢は2〜3個（多すぎない）
- 各選択肢に「当時の視点からは合理的に見える理由」を設ける
- 「正解」は史実の選択だが、それを押し付けない説明文にする
- 制約（財政・軍事・国際関係・国内政治）を必ず絡める

### 人物の選び方の目安
- 高校「歴史総合」「日本史探究」の教科書に登場する人物
- 明確な「決断の場面」が複数ある人物（単純な英雄譚にしない）
- 複数の視点・立場が存在する歴史的場面の中心人物

## UIデザインのルール

### カラーパレット（変更しない）
- ページ背景：`#ede4cc`（和紙クリーム）
- 対話ボックス：パーチメントグラデーション `#f5ead2` → `#ecddc0` → `#e6d6ae`
- 対話ボックス上辺：金・深紅の交互グラデーションライン（4px）
- ステージ（演技エリア）：`#080504`→`#201008`（暗いグラデーション）
- アクセント金：`#c8a84b`
- アクセント深紅：`#8b2020`
- 本文テキスト：`#1e1208`（濃いインク色）
- ネームプレート：`#1e1208`→`#2e1c0c` グラデーション・テキスト `#f0e6d0`

| 要素 | 値 |
|---|---|
| `.vn-stage` height | `420px` |

| 用途 | サイズ |

| 概念カード本文（`.concept-body`） | 13px |

### 結果画面の視覚ヒエラルキー（変更しない）
優先度の低い要素から高い要素の順に、視覚的に際立たせる：

1. **あなたの選択**（`.result-your`）：薄い青・小さめ → 自分の選択の確認用
2. **一致/不一致バナー**（`.match-banner`）：緑or黄 → ひと目でわかる判定
3. **桂太郎が実際に選んだこと**（`.result-katsura`）：緑ヘッダー付き最大枠 → **最重要・最目立ち**

新シナリオでも必ずこの3層構造を維持する。

### エンディングの歴史的概念カード
- 末尾に必ず4枚の概念カードを `<div class="concept-grid">` で配置する
- 各カードの色（`border-top`）は ① 深紅 ② 緑 ③ 青 ④ 茶 の順
- 内容はシナリオから自然に引き出される歴史的見方・考え方にする
- 例（桂太郎シナリオ）：制約の中の合理性 / 情報の非対称性 / 「勝利」の多面性 / 転換点の機会の窓

### 人物写真
- **Wikimedia Commons のパブリックドメイン写真を使用**
- URL は Wikipedia の各人物記事から実際に使われているサムネイル URL を取得すること（URL を推測すると 404 になることが多い）
- `onerror` は必ず `onPhotoError(this)` を使う。`this.style.display='none'` だけでは画像エリアが空白になる
  ```javascript
  function onPhotoError(img) {
    img.style.display = 'none';
    const sil = document.createElement('div');
    sil.className = 'char-silhouette';
    sil.innerHTML = SILHOUETTE_SVG;
    img.parentNode.appendChild(sil);
  }
  ```
- 写真がない場合はシルエットSVGを使用（`SILHOUETTE_SVG` 定数を参照）
- ページ末尾に必ずクレジット表記を入れる：「写真：Wikimedia Commons / パブリックドメイン」
- 写真URLの正しい取得方法：
  1. `WebFetch` で `https://en.wikipedia.org/wiki/[人物名]` を開く
  2. 返ってきたサムネイル URL（`upload.wikimedia.org/wikipedia/commons/thumb/...`）をそのままコピー

### タイマー
- グループ審議用タイマー：デフォルト1分（`TIMER_TOTAL = 60`）
- シナリオの難易度に応じて変更可（60〜180秒）
- `TIMER_TOTAL` を変更するだけで表示（`1:00`）とラベル（`1分`）が自動的に更新される（ハードコード不要）
